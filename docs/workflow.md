# OCR 校对与 Markdown 规范

## 一、多模式交叉校对

本书 441 页，超出 MinerU flash-extract 的 10MB / 20 页限制，统一使用
`mineru-open-api extract`（需在 https://mineru.net/apiManage/token 申请 token，
`mineru-open-api auth` 配置）。

`make ocr` 会跑两种模式：

| 模式 | 特点 | 用途 |
|------|------|------|
| `pipeline` | 无幻觉，逐字可靠 | **校对基准** |
| `vlm` | 复杂版式（脚注、引文混排）精度更高，偶有幻觉 | 交叉比对 |

校对方法：

1. 以 `ocr/pipeline/` 结果为底稿；
2. 用 diff 工具（如 `diff -u`、`code --diff`）对照 `ocr/vlm/` 结果，
   两处不一致的地方即为疑似识别错误，**对照原 PDF 页面**定夺；
3. 脚注混排、选文缩进等版式复杂处，以 vlm 结果为参照检查 pipeline 底稿；
4. 若需对个别疑难页第三次识别，可用 `--pages N-M` 单页重跑某一模式。

## 二、章节切分

校对后的正文放入 `manuscript/`，**每章一个文件**，文件名以两位序号开头
保证顺序，如：

```
manuscript/00-frontmatter.md     # 扉页、出版信息、序言
manuscript/01-前言.md
manuscript/02-第一章-xxx.md
...
```

pandoc 按文件名排序合并，构建时自动生成目录。

## 三、Markdown 书写约定

### 标题

- 每章文件以一级标题开头：`# 第一章 xxx`
- 章内小节用 `##`、`###`

### 脚注

统一使用 pandoc **行内脚注**，脚注内容直接跟在正文之后：

```markdown
正文文字^[这是脚注内容。]继续正文。
```

不要用 `[^1]` 编号式脚注——OCR 合并多页内容时编号极易错位，
行内脚注没有编号，不存在漂移问题。

### 选文（作品原文引用）

短选文用块引用：

```markdown
> 枯藤老树昏鸦，小桥流水人家……
```

长选文（含多个段落、标题）用 fenced div，EPUB 中有独立样式：

```markdown
::: {.xuanwen}
**《春》朱自清**

盼望着，盼望着，东风来了……
:::
```

诗歌等需保留换行的选文，段内换行用行尾两个空格或 `\` 结尾。

### 字体分工（由 assets/epub.css 实现，跨平台回退到各系统字体）

| 内容 | 字体 | Markdown 写法 |
|------|------|---------------|
| 正文 | 宋体 | 普通段落 |
| 标题、着重 | 黑体 | `#`/`##` 标题、`**着重**` |
| 选文、引文、诗歌 | 楷体 | `> ` 或 `::: {.xuanwen}` |
| 扉页信息、题辞、出版说明 | 仿宋 | `::: {.fangsong}` |

### 其他

- 强调用 `**着重**`（对应原书着重号/加粗）；
- 书名号《》保留原样，不要改成斜体；
- 页眉、页码、书脊文字等杂质一律删除；
- 拿不准的字，在行间加 HTML 注释 `<!-- 疑：原书作「x」 -->` 留待复核。
